# mihomo-x 使用说明

这是 Windows 原生 Mihomo 客户端。交付目录包含原生运行时，请保留整个目录，运行 mihomo-x.exe。当前版本默认申请管理员权限，以支持 TUN。

## 界面

侧边导航分为概览、配置、节点和设置。窄窗口通过左上角菜单打开导航，选中页面后自动收起。系统代理、TUN 和桌面行为使用中文开关；成功或错误反馈显示在页面底部，可手动关闭。配置重命名和高级 YAML 默认折叠。

## 连接

1. 在“配置”页面选择本地 YAML 文件，或输入 HTTP/HTTPS 订阅 URL，点击“导入配置”。
2. 点击“使用配置”，然后在“概览”页面点击“启动内核”。规则、全局、直连控制 Mihomo 的路由模式。
3. TUN 和 Windows 系统代理是独立开关。TUN 的路由、DNS 等配置来自 profile 或合并设置。系统代理需要 profile 开启 HTTP 或 mixed 监听端口。
4. 在“节点”页面选择策略组节点，可以搜索节点名称并检测 HTTPS 延迟。延迟检测不代表带宽或所有网站可用。

## 配置

导入副本保持原字节，不修改源文件。更新从原文件或订阅 URL 读取，失败保留旧内容。“设置”页面底部的“高级配置 · 合并 YAML”接受 YAML mapping，合成运行配置，不写回 profile。

## 桌面行为

“开机启动”在当前用户登录 Windows 时以最高权限启动应用；关闭即删除本应用的计划任务。移动分发目录后请重新开关该选项。

应用启动后检查 GitHub 私有仓库的新版本，也可以在设置页检查。发现新版后选择“更新并重启”，应用校验下载包后自动退出、替换文件并重启。需安装并登录 GitHub CLI，拥有 `zogwosh/mihomo-x` 仓库访问权限。更新失败日志保存在数据目录的 `app-update.log`，旧应用文件保存在该次更新目录中。

“设置”页面可切换启动自动连接、启动隐藏、关闭窗口隐藏到托盘或直接退出。启动选项在下次启动生效。窗口位置和尺寸定期保存。托盘单击恢复窗口，右键菜单可退出。

停止内核或退出 app 会恢复本 app 接管前的系统代理设置；其他软件后来修改的值保留。强制结束 app 后，遗留代理设置在下一次启动恢复。若无法重新启动 app，可通过 Windows 设置手动检查代理。

## 诊断和更新

可直接打开内核日志和数据目录。脱敏诊断导出只包含版本、运行模式、TUN、配置数量及文件存在状态、日志大小；不包含配置原文、订阅 URL、节点名称、日志内容或控制器密钥。

内核更新来自 MetaCubeX/mihomo 的官方稳定 Release，显示下载进度，校验 SHA256，失败时尝试恢复旧内核。te 尚无发布仓库和许可证，应用自身更新及公开发布暂缓。

设置损坏时可选择先备份再恢复 profile 列表；配置原文件保留，订阅来源等记录需重新设置，自动连接会关闭。

当前实际验证平台为 Windows Sandbox x64，已验证 TUN 与系统代理同时运行、设置只读恢复和升级替换失败恢复。Windows 10、ARM64、真实订阅节点及其余升级失败路径仍需单独验收。
