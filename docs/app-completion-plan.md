# 完整 app 开发计划

按稳定性、系统代理、配置管理、日常界面、诊断、桌面体验、更新交付、发布验收推进。保留 Rust / WinUI 与独立 Mihomo 子进程；不新增测试或架构层。

## 已实现，仍需按下列范围验收

- 配置切换与合并设置：停止旧内核前调用 Mihomo 检查配置；新配置启动或设置保存失败时恢复旧设置和运行状态。
- 模式、TUN、节点：设置写入失败时尝试恢复此前的 API 状态，并报告恢复失败。
- 系统代理：独立开关、读取实际监听端口、持久化用户选择、内核就绪后应用、端口改变时同步、停止或退出恢复原设置。
- 系统代理恢复记录：下一次启动清理异常退出遗留设置；当前设置与本 app 写入值不一致时保留其他软件或用户的修改。
- 配置管理：本地文件和 HTTP/HTTPS URL 导入、从原来源手动更新、更新时间、重命名、移除确认、失败保留旧内容。
- 节点搜索、当前节点标记、逐节点 HTTPS 延迟检测。
- 日志追加；启动时达到 4 MiB 后保留一份历史日志；打开日志、数据目录入口。
- 操作处理中提示、显式退出按钮、重复启动唤起已有窗口。
- 内核升级：在停止前备份，替换或重启失败后恢复旧内核。
- 界面分为配置、节点、设置与诊断页面；显示当前配置、模式和 TUN 状态，停止时区分启动选项与实际运行状态。
- 订阅来源只显示主机名；下载错误去除 URL；脱敏诊断仅导出明确允许的状态字段。
- 启动自动连接、启动隐藏、关闭到托盘或退出可配置；保存和恢复窗口位置、大小及最大化状态。
- 托盘显示运行状态，提供启动/停止、系统代理、TUN、规则/全局/直连操作。
- 嵌入多尺寸 te 图标，无额外运行依赖。
- 损坏的 settings.json 可明确选择备份并恢复 profile 列表；恢复后自动连接关闭。
- 内核下载显示进度和校验阶段；配置验证进程归入 Job，超过 60 秒取消。
- 后台刷新期间的用户操作排队执行；退出会等待当前操作完成。
- 打包按 PE 架构选择 CRT，提供版本化 ZIP 和文件/ZIP SHA256；排除沙箱部署生成的 AppX 副本。

## 接下来完成

1. 继续补齐负向验证：无效节点、下载失败、SHA256 不匹配和新内核启动失败。端口占用、设置不可写、升级替换不可写及损坏设置恢复已经实测。
